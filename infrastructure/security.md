# Security

## Principles

- **Nothing exposed to the internet.** The only way in from outside is WireGuard.
- **Default deny.** Every running host drops incoming traffic unless a rule allows it.
- **One way in per service.** Web services are only reachable through the reverse proxy. Their own ports are closed to the rest of the network.
- **No secrets in documentation.** Passwords and keys live in `.env` files (chmod 600) on the hosts, and never in this repo or in chat logs.

## Firewalls

| Host type | Firewall |
|-----------|----------|
| Proxmox host | Proxmox firewall (cluster + host level, policy DROP) |
| VMs and LXC containers | ufw (default deny incoming) or iptables-persistent |
| Raspberry Pi 5 | ufw |

Only the ports that are really needed are open, and usually only from one source. For example, a service port only accepts traffic from the reverse proxy, and exporters only accept traffic from the monitoring container.

## Docker bypasses ufw

This was the biggest lesson of the firewall rollout. **Ports published by Docker skip ufw completely**: Docker writes its own iptables rules that are evaluated before ufw's. On a Docker host, ufw by itself gives a false sense of security.

The fix is the `DOCKER-USER` chain, which Docker evaluates before its own forwarding rules:

```
1. RETURN  established / related connections
2. RETURN  container ↔ container traffic on the Docker bridge
3. RETURN  reverse proxy → service port
4. RETURN  outbound traffic to the internet (-o <uplink NIC>)
5. DROP    everything else
```

Things I ran into along the way:

- **Rule 4 is essential.** Without an egress rule, the final DROP also blocks containers from reaching the internet. That happened right after the rollout, when every search engine behind SearXNG started timing out.
- **Match the port after DNAT.** `DOCKER-USER` sees the container port, not the published host port. A service published as `8080 → 80` needs a rule for port 80.
- **Don't snapshot the nat table.** The first version restored a full iptables snapshot at boot. After a power cut the containers came back with new IP addresses, and the restored NAT rules pointed at containers that no longer existed. Now a small script fills only `DOCKER-USER`, and Docker manages NAT itself.
- **Re-apply when Docker restarts.** The restore runs as a systemd unit with `PartOf=docker.service` and `Restart=on-failure`, so a Docker restart reapplies the rules automatically.

The actual script and unit: [`firewall/restore-docker-user.sh`](firewall/restore-docker-user.sh) and [`firewall/docker-ufw-restore.service`](firewall/docker-ufw-restore.service).

## VPN

WireGuard via wg-easy on the Raspberry Pi 5:

- Family devices: full tunnel with Pi-hole DNS.
- Guests: split tunnel that only reaches the reverse proxy and DNS.
- Keys are generated by wg-easy and never pasted into chats or notes.

## Certificates

A private PKI (step-ca) issues the TLS certificates for all internal services. The root key is backed up outside the CA container. See [network](network.md#reverse-proxy-and-https).
